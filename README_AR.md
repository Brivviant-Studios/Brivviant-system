# Brivviant Studio — V12 Project Workflow

هذه الحزمة تطوّر **نفس النظام الأصلي** ولا تستبدل الواجهة. `index.html` في الجذر ما زال يشغّل ملفات FINAL V10 الأصلية، بينما وظائف V12 مضافة بشكل additive من خلال `v11-patch.js` و`v11-patch.css` وService Worker.

## الرفع على GitHub Pages
فك الضغط وارفع **محتويات الحزمة كما هي إلى جذر المستودع**. لا تحتاج إلى npm أو Build لتشغيل النسخة الجاهزة. تأكد أن `index.html` و`assets/` و`v11-patch.js` و`v11-patch.css` و`sw.js` و`manifest.webmanifest` و`config.js` موجودون في الجذر.

## أهم وظائف V12
- طلب الإجازة يعمل من أول محاولة ولا يحتاج طلبًا سابقًا.
- سبب رفض الطلب/الإجازة يظهر لصاحب الطلب، والمحاولة الثانية بعد الرفض تُصعّد للإدارة.
- نقل التاسك إلى «تم التسليم» يؤرشفه بدل حذف السجل؛ التسليمات والوقت والنقاط والـAudit تظل محفوظة.
- Workflow بالمراحل والساعات: مراجعة البريف، Direction، Modeling/Elements، Rendering، Finalization، Delivery، مع مسؤول وساعات لكل مرحلة واعتماد قبل الانتقال للمرحلة التالية.
- النقاط تُحسب على المشروع كاملًا عند الاعتماد النهائي حسب الساعات المخططة مقابل الفعلية. تعديل بسبب خطأ من الشخص أو Pause بسبب تقصيره يصفر نقاطه في المشروع.
- الإدارة تستطيع إضافة أو خصم نقاط يدويًا مع سبب إلزامي.
- CEO يستطيع رؤية Task Owner، المعتمد، ملاحظة الاعتماد، التعديلات، وملاحظات الجودة.
- إنشاء التاسك بالصوت يستخدم `GEMINI_API_KEY` الموجود في Supabase Secrets مع Model Pool وFallback للطريقة العادية عند نفاد/تعطل الموديلات.
- إشعارات غير مقروءة Highlighted، مع Web Push للموبايل/PWA بعد منح إذن الإشعارات من المتصفح/النظام مرة واحدة.
- زر AR / EN في الشريط العلوي وصياغات أكثر احترافية للواجهة.

## Supabase
تم تطبيق V12 بالفعل على مشروع Studio الحالي بتاريخ 1 أكتوبر 2026، وتم نشر `brivviant-voice-task` و`brivviant-push`. ملف `database/20261001_v12_project_workflow.sql` موجود للمراجعة أو لأي بيئة جديدة، وليس مطلوبًا إعادة تشغيله على مشروع Studio الحالي.

لا تضع `GEMINI_API_KEY` أو Service Role Key داخل ملفات GitHub. مفتاح Gemini يظل داخل Supabase Edge Function Secrets فقط.
